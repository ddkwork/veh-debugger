# VEH Debugger v1.2.1

### Added
- **Bounded MCP analysis transport** -- `veh_batch` can start an unattached session with one first-step launch/attach, then run analysis in the same request. Steps can return selected dotted result fields while retaining full values for later references. A total response-byte budget spills oversized reports to generated non-overwriting MCP-host JSON artifacts with path, SHA-256, size, count and explicit partial metadata. `veh_toolbox manifest` fetches and revalidates up to 64 workflow schemas in one call, reducing repeated discovery round trips.
- **Structured backend startup diagnostics** -- an optional inherited pipe carries one fixed common error/detail record before IPC is ready. Remote startup failures show validated reasons alongside actual agent exit and OS codes, without mapping backend-specific exit numbers or forwarding logs. Existing agents retain numeric diagnostics.
- **Authenticated remote backend connections (MCP)** -- registered TCP profiles use pinned TLS and one authentication per connection. A resident runner owns backend startup, host process launch and bounded reconnect leases; remote PIDs are never treated as local PIDs. Driver analysis VMs and VirtualBox/WHPX analysis host VMs share the transport. Guest process launch, frontend conditional breakpoints and target-side trace file pipes remain explicitly unsupported; backend capabilities stay authoritative.
- **External host-process backends** -- attach and launch can select a registered backend or explicit agent through the shared IPC protocol without DLL injection. Host launches start suspended; command capability reporting identifies unsupported operations.
- **System inspection through external backends** -- tools expose physical/kernel memory access, address translation, MSR/CPUID, I/O ports, IDT/APIC, PCI and kernel-module inspection. Each operation requires a supporting backend; the VEH DLL does not implement these machine-level commands.
- **Kernel debugging over GDB RSP** -- independent machine-wide debugging supports pipe/COM/TCP/UDP transports, CPU registers, memory, stepping, breakpoints and watchpoints. Requires a compatible remote stub and can halt the whole target machine.
- **System events, hidden hooks and branch tracing** -- supporting hypervisor backends can expose filtered machine events, event records, hidden execution hooks, LBR snapshots and Intel PT branch records. Hardware/backend availability determines support.
- **Address-space selection and timing transparency** -- supporting backends can resolve and select a validated target page-table root and configure debugger-time compensation; these interfaces do not add those capabilities to the VEH DLL.
- **Timed memory-access collection** -- `veh_trace_memory.duration_ms` collects write or combined read/write hits by instruction location, with hit counts, first-thread registers and explicit `dropped_hits`. Omitting `duration_ms` preserves the original first-write mode. On the VEH backend, locations are marked `addressIs="next_instruction"` and registers describe the state after the first access; read-only collection and per-hit read/write classification are not supported.
- **VM attachment without a process (MCP)** -- `veh_attach` accepts `target_scope="vm"` with an external backend and no PID. The frontend validates explicit VM metadata, opens no host target handle, starts no target process monitor, and omits `--pid` for VM agents. Invalid VM arguments preserve the current session; guest-process PID/width validation remains separate.
- **Explicit VM control and vCPU instruction trace (MCP)** -- `veh_virtual_machine` uses versioned backend IPC for whole-VM status/pause/resume and one bounded paused-vCPU interpreter batch. CR3/CPL/RIP boundaries stop before execution; returned records retain exact timestamps and completion/loss counts, including partial failures. It is independent of the guest PID and does not imply selective thread stops. Manual/toolbox calls are supported; process-scoped batch/capture/actions intentionally exclude VM-wide execution.
- **External guest attachment (MCP)** -- `veh_attach` accepts `target_scope="guest"` directly or through a registered backend. The backend validates PID and 32/64-bit metadata, without opening or monitoring the same numeric host PID. Agent reuse checks executable, arguments and scope. Guest process discovery and guest launch/stopOnEntry remain unsupported.

### Changed
- **Remote runner distribution** -- binary ZIP and VSIX preparation now include `veh-remote-runner.exe` alongside the adapter, MCP server and both payload DLLs. Archive validation rejects a missing runner.
- **Event-driven MCP waits** -- the main loop, heartbeat and kernel-debug pipe wait for input or events instead of periodic timer polling.

### Fixed
- **Accurate backend failure results** -- thread/module queries and dynamic traces distinguish backend rejection, malformed replies and transport failures from valid empty results. Disconnected remote agents no longer imply a target crash, and trace errors preserve backend status instead of guessing a missing stop or hook.
- **Remote startup diagnostics** -- failed work opens now report a fixed startup stage, the agent's real exit code (decimal and hex) when it exited, and Windows API error codes when available. Values are captured before cleanup; backend logs, arguments and private paths are not forwarded.
- **Remote reconnect admission** -- successful authentications no longer consume a per-address connection quota. Failed authentication remains limited, pending proofs reserve failure slots, and successful sessions do not erase prior failures.
- **Repeated remote attachment** -- reattaching the same backend/scope/PID completes the old remote detach and waits for resident connection closure before opening the replacement. Missing closure is reported instead of returning a premature detach success.
- **Remote backend lifetime recovery** -- detach ends a work even without an acknowledgement; closing/dead agents are excluded from reattachment and exact process-handle notifications cancel dead connections. Host targets survive backend death, while retired launch identities still prevent duplicate creation. Rapid detach/attach no longer selects jobs waiting for cleanup.
- **VEH lifecycle acknowledgements** -- Detach and Shutdown keep their final reply available until the client closes, with a bounded drain wait instead of immediately discarding buffered data or flushing forever.
- **Remote long-running commands** -- a pending command now keeps its TCP connection through idle input intervals, using the bounded backend command deadline; response delivery remains in flight until complete.
- **Remote launch failure recovery** -- failures before OpenWork delivery and explicit resident rejections clear launch retry state. Lost or ambiguous replies retain the same request identity, preventing duplicate process creation on retry.
- **In-flight breakpoint removal** -- a debugger INT3 dispatched after its breakpoint was removed now replays the restored instruction instead of skipping its first byte as a program-owned DebugBreak. This prevents instruction corruption and target crashes during repeated caller traces; original program INT3 instructions retain their normal handling.
- **Pipe connection diagnostics** -- connection timeouts retain the last pipe error instead of reporting an uninformative timeout alone.
- **Caller trace leaving a hypervisor target suspended** -- `veh_trace_callers` no longer sends its automatic continue and pause to the hypervisor backend, whose hidden hook needs no resume. The pause after collection suspended every thread of a running target until the debugger detached. The VEH DLL backend keeps its resume and pause around the INT3 trace.
- **Step refusals reported at once** -- `veh_step_in`, `veh_step_over` and `veh_step_out` treat every non-Ok backend status as a refusal with its reason, instead of only "not found". A backend that cannot step a thread suspended by pause/freeze (no stop to step from) now answers immediately rather than after the five-second step timeout.
- **Caller trace with no calls** -- a window in which the function was not called returns `totalHits: 0` instead of a stale transport error ("IPC communication failed"); a backend refusal is reported as such.
- **Explicit breakpoint capacity failures** -- backends can return `IpcStatus::LimitReached` when breakpoint slots are exhausted. MCP software/source/function/data breakpoint calls report capacity exhaustion instead of a generic failure; the VEH DLL reports it when its four hardware slots are occupied. Existing profiles, tool schemas and gateway routing are unchanged; numeric capacities are still not negotiated.
- **Stale continue stop events** -- `veh_continue` discards earlier stop events for threads it has resumed and, when the backend supports stopped-state queries, verifies that a thread is still stopped before reporting it. This avoids reporting an already-resumed thread as stopped before a trace request.
- **Backend-neutral breakpoint errors** -- a failed data-breakpoint request no longer assumes every backend has four hardware slots; numeric backend capacities are not negotiated by the current capability protocol.
- **Caller trace duration compatibility** -- `veh_trace_callers` returns both `durationMs` and the legacy `durationSec` field. Whole seconds retain integer values; subsecond windows use fractional seconds without rounding. Both `duration_sec` and `duration_ms` inputs remain supported, with milliseconds taking precedence when both are provided.
- **Guest launch routing** -- unsupported guest launch rejects before host process creation or replacement of the current session.
- **Unsupported backend results** -- pause and terminate no longer report success when unsupported; rejected termination preserves the session.
- **Backend help and setup** -- attach/launch descriptions, argument help, CLI help, Korean/English READMEs and extension MCP documentation now distinguish native host debugging from external guest attachment and its limits.
- **Shellcode IPC wait budget** -- execution waits use the requested timeout plus backend setup and cleanup time, so valid runs longer than three seconds do not fail at the transport's default deadline.
- **Missing compare-exchange trace writes** -- `veh_trace_basic_blocks` now records memory writes for `cmpxchg`, `cmpxchg8b`, and `cmpxchg16b`, with or without `LOCK`, in inline events, `.vte` streams, and aggregate write tables. Both successful exchanges and failed comparisons carry actual before/after bytes; failed comparisons and successful same-value stores remain write events even when the bytes are unchanged.
- **Conditional operand dependency gaps** -- register dependency tracking includes conditional reads and writes and conservatively retains a conditional destination's previous origins. Memory-source `cmov` reads are collected on either outcome. Other conditional or masked memory accesses whose executed bytes cannot be determined are reported as unsupported instead of silently omitted or fabricated as full-operand accesses; dependency results are marked incomplete when an unsupported memory access is encountered.
